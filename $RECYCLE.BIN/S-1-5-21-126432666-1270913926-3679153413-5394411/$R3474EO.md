# Applying Personalization

Teamcenter X supports applying personalization changes to a customer deployment. Personalization changes can be classified into two categories:

1. **Data model or schema changes** applied through a DC package file using DC. These changes require downtime for the deployment.
2. **Admin data** like stylesheets, workflow handlers, values of OOTB preferences, localized values, and AW Client UI configuration. These changes used to be deployed manually using a shell script that invokes one or more command-line utilities to add the admin data—mainly to avoid downtime for the deployment when these changes are applied through DC. 

> **Note:** DC supports zero-downtime admin data updates from the TcX 2412 release onwards.

For customer preprod/uat and production environments, the expectation is that personalization changes, including admin data, will be applied using the deploy automation pipeline. There will be zero manual steps required to deploy in these environments. The existing manual tasks associated with admin data must be brought into the scope of DC deployment as discussed in section [Applying admin data personalization changes](./Applying%20admin%20data%20personalization%20changes).This is a change from how personalization has been applied in the past and is a step in the right direction. 

> **Important:** Applying personalization changes will require downtime. As the updates to these environments typically require downtime, the personalization updates can be applied during this period.

The personalization changes are usually applied through software packages/kits as a post-deployment step to an existing deployment. However, it can also be included as part of an initial deployment for UAT and production deployments and re-applied as part of an update/upgrade.

> **Note:** As the personalization kits will be used across multiple deployments for a single customer, they must be placed in a common location that can be accessed by those deployments. As part of the first deployment created for a customer/tenant, the DeployOps automation pipeline creates a common tenant storage with a name in the format.
```
AWS: tcx-tenantbucket-<tenant AWS region>-<tenant id>-<AWS Account number> 
AZURE: tcxt<tenant_id>cm<tenant_infix>sa<subscription_id_prefix>
```
This cloud storage is accessible to all deployments of a customer/tenant in the specific region. The CApS team should place the personalization kits in folders inside this tenant storage.
