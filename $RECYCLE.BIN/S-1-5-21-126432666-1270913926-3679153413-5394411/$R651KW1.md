## Modify the network to allow CAPS to perform AD join for CyberArk connection

The `tcx-tenant-pipeline` adds the CAPS management plane CIDR to the tenant NAT route table. In order to perform the AD join, CAPS needs to run an Ansible workflow that handles all the networking. However, during the workflow execution, it attempts to add the CAPS management CIDR to the tenant NAT route table, but the workflow fails with a "route already exists" error because the `tcx-pipeline-tenant` has already added a route in the tenant route table.

To mitigate the issue and smoothly perform the AD join, follow the steps below:

1. Log in to the AWS console where the tenant is deployed.
2. Navigate to the **Route Tables** section.
3. Select the tenant-specific route table (`Siemens-<tenant_id>-NAT-RT-1`).

    ![Route Table](./image_351.png)

4. Go to the **Routes** tab.

    ![Routes Tab](./image_352.png)

5. Click **Edit Route**.
6. Remove the `10.149.18.0/23` entry from the routes.

    ![Edit Route](./image_353.png)

7. Click **Save Changes**.
8. Navigate to **Security Groups**.
9. Open the `Siemens-{tenant_id}-DCServer-SecurityGroup` security group.
10. Go to the **Outbound Rules** tab.
11. Remove the rule with the destination `10.149.18.0/23`.

     ![Outbound Rules](./image_354.png)

Once these changes are complete, you can trigger the Ansible workflow.
