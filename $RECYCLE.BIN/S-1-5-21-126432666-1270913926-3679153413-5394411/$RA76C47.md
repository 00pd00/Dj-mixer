# VM Resize Operation

## 1. Description
This Operation automates the process of resizing VMs for hybrid products based on user defined VM size for each VM.

## 2. Pre-requisites
- Access to  [Ansible tower](https://ansible-tcx-prod.plmcloudsolutions.com/) 
- The deployment must be **Variable VM infra** based deployment.
   - Currently **Variable VM infra** is supported only for **AWS** deployments  (available from 2512+).
- The deployment must be **PID based deployment** not **Static QD based deployment**.
- The user must verify that both new VM size and VM class are compatible with the hybrid product being resized.
- This operation must be performed in maintenance window as it requires system downtime of around 20 minutes.

## 3. Operation Preparation Details
#### 3.0.1. Identify the MachineIDs of the VMs to be resized
- The required information about the current VM boxes for a cTcX deployment can be retrieved from the respective tenant repo.   
    - In the tenant repo, open file `<Tenant-Repo>/customer-information/pipeline-output.md`

- In pipeline-output.md file, the VM details are listed in tabular format in **AWS Details** section as shown below:
    - Here, user gets an overview of the products installed on various VMs along with their current usage.

    ![AWS Details](./image_380.png)

    - `Note the MachineIDs and current Usage values of the VMs to be resized. This information will be required while executing the workflow.` 
    - Users can resize single or multiple VMs at a time. Each machine can be individually resized using MachineID.

#### 3.0.2. Identify the target usage for VMs to be resized
- To prevent accidental selection of oversized instances, the cTcX pipeline supports a range of cloud-agnostic VM sizes. Users must choose values within this permitted range only for each VM.
- `Below are the supported TcX VM sizes:`

    **Usage class: Compute Optimized (CO) Family**

    | Usage Values | AWS Instance type |
    |:------------:|:----------------:|
    | TCX_COVM.standard | c7i.xlarge |
    | TCX_COVM.large | c7i.2xlarge |
    | TCX_COVM.4xlarge | c7i.4xlarge |
    | TCX_COVM.8xlarge | c7i.8xlarge |
    | TCX_COVM.12xlarge | c7i.12xlarge |
    | TCX_COVM.16xlarge | c7i.16xlarge |
    | TCX_COVM.24xlarge | c7i.24xlarge |

    **Usage class: General Purpose (GP) Family v1**

    | Usage Values | AWS Instance type |
    |:------------:|:----------------:|
    | TCX_GPVM.standard | m7i.xlarge |
    | TCX_GPVM.large | m7i.2xlarge |
    | TCX_GPVM.4xlarge | m7i.4xlarge |
    | TCX_GPVM.8xlarge | m7i.8xlarge |
    | TCX_GPVM.12xlarge | m7i.12xlarge |
    | TCX_GPVM.16xlarge | m7i.16xlarge |
    | TCX_GPVM.24xlarge | m7i.24xlarge |

- Users can select appropriate usage values depending upon their requirement for each MachineID identified in above step.
    - `Note: Users need to ensure that the selected usage values and usage classes are compatible with the hybrid product being resized.`

#### 3.0.3. Create MachineID to Usage map
- After identifying the MachineIDs and target usage values for the VMs to be resized, create a map of MachineID to Usage like below:
    ```yaml
    <MachineID1>:
        Usage: <TargetUsage1>
    <MachineID2>:
        Usage: <TargetUsage2>
    ```

- For Example, if you want to resize,
    - AIGServer1 from TCX_COVM.4xlarge to TCX_COVM.8xlarge
    - TcRAServer1 from TCX_GPVM.2xlarge to TCX_GPVM.8xlarge

    the map looks like below:
    ```yaml
    AIGServer1:
        Usage: TCX_COVM.8xlarge
    TcRAServer1:
        Usage: TCX_GPVM.8xlarge
    ```

## 4. Operation Execution Details
#### 4.0.1. Prepare input for Operations Pipeline
- The operation is executed using the RunCommands template in Ansible Tower. The following customer inputs are required to execute the workflow:

    | Parameter | Value | Example |
    |-----------------|-------|------------|
    | CustomerID | CustomerID ( Note: If the customer ID is numeric only, <br/>enclose it in single quotes, e.g., `'12345'`). | deploy123 |
    | Description | Description for information | Resize VM instances | 
    | Environment | The type of environment deployed. | prd |
    | StreamId | Configuration file for loading parameters.<br/> Supported values: [dev, dryrun, internal, customer].| dev |
    | TcXVersion | The version of TcX to be used for operation.<br /> This value refers to the tag of the tc-version-manifests project in gitlab. | br.2512.0000 |
    | PipelineStage | The stage of the pipeline to run: operations | operations |
    | PipelineVersion | tcx-pipeline-tenant repo branch or tag for pipeline. | main |
    | OperationsAction | Action to perform | resize_vm_instances |
    | ResizeInstanceMap | The map of MachineID to Usage created in above step. <br /> This is a YAML formatted string. | AIGServer1:<br />&nbsp;&nbsp;&nbsp;&nbsp;Usage:&nbsp;TCX_COVM.8xlarge<br />TcRAServer1:<br />&nbsp;&nbsp;&nbsp;&nbsp;Usage:&nbsp;TCX_GPVM.8xlarge |

- For example, the customer input will look like:
    ```yaml
    CustomerID: rapid128
    Description: Ctcx resize vm instances
    Environment: prd
    StreamId: dev
    TcXVersion: br.2512.0000
    PipelineStage: operations
    PipelineVersion: main
    OperationsAction: resize_vm_instances 
    ResizeInstanceMap:
        WindowsServer1:
            Usage: TCX_GPVM.4xlarge
        CorpServer:
            Usage: TCX_COVM.4xlarge
    ```

#### 4.0.2. Initiate the workflow
- Use RunCommands Template to perform operation. Please refer [Ansible Templates Table](../../Tenant%20Onboarding/Basic%20Flow/Ansible%20Templates%20Table)

- In Survey, provide the [Customer Input created in above step](#1-prepare-input-for-operations-pipeline), GITLAB PAT token, and Vault Token.

![Image](./image_358.png)

- Click on 'Next -> Launch' to initiate the resize vm operation.
- A new operation pipeline will be created in gitlab which will execute the resize operation on the specified VMs.

## 5. Verification on completion
#### 5.0.1. Verify VM resize via AWS Console
- Login to AWS console and navigate to EC2 dashboard.
- In the **EC2 dashboard**, navigate to **Instances** section.
- Filter the instances using CustomerID and verify if the required VMs are resized to target instance types.

#### 5.0.2. Verify VM resize via pipeline-output.md
- After the workflow is completed successfully, navigate to the tenant repo and open file `<Tenant-Repo>/customer-information/pipeline-output.md`
- In pipeline-output.md file, the updated VM details are listed in tabular format in **AWS Details** section.

    - `Note the MachineIDs and current Usage values of the resized VMs. Verify if the required VMs are resized to target instance types.`

## 6. Troubleshooting
### 6.1. Common gitlab operations pipeline errors
| Error Message | Cause | Resolution |
|---------------|-------|------------|
|Unexpected templating type error occurred on (`{{ lookup(''file'', ''/srv/tenant/customer-information/machine_components_map.json'', errors=''ignore'') \| from_json }}`): the JSON object must be str, bytes or bytearray, not NoneType. the JSON object must be str, bytes or bytearray, not NoneType | The deployment on which the operation is being performed is not a Variable VM infra based deployment. | Verify that the deployment is a Variable VM infra based deployment. This operation is supported only for Variable VM infra based deployments. |
| Instance type '&lt;desired_instance_type&gt;' for machine ID '&lt;desired_machine_id&gt;' is not supported. | The requested instance type is not supported by cTcX | Choose a different instance type that is supported provided in [section 3.0.2 above](#302-identify-the-target-usage-for-vms-to-be-resized). |
| No machines need resizing. All requested machines are already at the requested instance types. | Provided target usage values for all specified MachineIDs are same as current usage values. | Verify the target usage values provided in ResizeInstanceMap. Choose different target usage values for the specified MachineIDs based on [step 3.0.1 above](#301-identify-the-machineids-of-the-vms-to-be-resized). |
| Operation not supported: Static QD based deployment detected. | The deployment on which the operation is being performed is a Static QD based deployment. | This operation is not supported for Static QD based deployments. Only PID based deployments are supported. |
| Machine ID '&lt;target_machine_id&gt;' not found in machine component map. | One or more specified MachineIDs in the ResizeInstanceMap does not exist in the deployment. | Verify the MachineIDs provided in ResizeInstanceMap. Ensure that the MachineIDs exist in the deployment. Refer section [step 3.0.1 above](#301-identify-the-machineids-of-the-vms-to-be-resized) |
