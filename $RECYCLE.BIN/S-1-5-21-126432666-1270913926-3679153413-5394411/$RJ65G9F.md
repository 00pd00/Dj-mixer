# Egress: Manual Steps to Rotate Teamcenter X client_id Shared with External Systems (xApps)

The Teamcenter X pipeline generates a client_id used to make outbound calls to external systems (xApps). This credential is stored in HC Vault at:
  ```
  <environment-namespace>/tcx/teamcenter/administration/client_credentials/common/client_id
  ```

In case of security incidents, this secret needs to be rotated. This guide explains how to set up and configure the SAM Lambda, which helps in creating new xApp client credentials required for secret rotation.

## Step 1: Generate SAM App ID and new xApps Client Secret

### Prerequisites

- **AWS CLI**: Must be installed and configured with valid credentials using `aws configure`.
  - On Linux, AWS CLI is usually pre-installed.
  - You may also use a session token (`aws sts assume-role`) if needed.
- **Lambda Access**: Your AWS account must have access to  
  `arn:aws:lambda:us-east-1:361500002652:function:tcx_cli:PRD`.  
  Contact the CApS team to request access if necessary.
- **Tenant SAM Account Credentials**: You need the `SAM_ACCESS_KEY` and `SAM_SECRET_ACCESS_KEY` for the tenant.
- **SAM App Name**: You need the `SAM_APP_NAME` for the tenant.
   For xApps Client, the SAM_APP_NAME for a tenant can be generated as per the format below:
   `tcx-<dnsSubdomainName>-<Environment>-adminutils`
   e.g. for a tenant, 'dnsSubdomain: dchpa5uat', 'Environment: prd' then, 'SAM_APP_NAME: tcx-dchpa5uat-prd-adminutils'
- **SAM App ID**: You need the `SAM_APP_ID` for the tenant. This will be generated by using below Lambda.

### Procedure: Generate SAM App ID (Customer/DryRun Environments)

1. Open your terminal (Linux) or Command Prompt (Windows).
2. Use the following command to invoke the lambda function and generate the appId.

   **Linux:**
   ```bash
   aws lambda invoke --region us-east-1 --function-name arn:aws:lambda:us-east-1:361500002652:function:tcx_cli:PRD --cli-binary-format raw-in-base64-out --payload '[["<SAM_ACCESS_KEY>","<SAM_SECRET_ACCESS_KEY>","us-east-1.sws.siemens.com"],["samauth","ListApps","<SAM_APP_NAME>"]]' appid_output.txt
   ```

   **Windows:**
   ```cmd
   aws lambda invoke --region us-east-1 --function-name arn:aws:lambda:us-east-1:361500002652:function:tcx_cli:PRD --cli-binary-format raw-in-base64-out --payload "[[\"<SAM_ACCESS_KEY>\",\"<SAM_SECRET_ACCESS_KEY>\",\"us-east-1.sws.siemens.com\"],[\"samauth\",\"ListApps\",\"<SAMAUTH_APP_NAME>\"]]" appid_output.txt
   ```

### Result

If the process succeeds, open the 'appid_output.txt' file, you will receive output similar to:

```json
{
  "apps": [
    {
      "appId": "d724a7c513cb424eac27e0aede465fa7",
      "name": "tcx-dchpa5uat-prd-adminutils",
      "displayName": {
        "default": "tcx-dchpa5uat-prd-adminutils"
      },
      "status": "Unapproved",
      "appUris": [
        "http://localhost:4010"
      ],
      "expiry": 1771961835053
    }
  ]
}
```

Keep the following values for future steps:

| Value to Copy       | Description                                         | Parameter Name (Key)          |
|---------------------|-----------------------------------------------------|-------------------------------|
| appId               | App Id of SAM App which holds xApps Client          | `SAM_APP_ID`                  |
| name                | App Name of SAM App which holds xApps Client        | `SAM_APP_NAME`                |

---

### Procedure: Generate new xApps Client Secret (Customer/DryRun Environments)

1. Open your terminal (Linux) or Command Prompt (Windows).
2. Use the following command to invoke the lambda function and generate the new xApps Client Credentials.

   **Linux:**
   ```bash
   aws lambda invoke --region us-east-1 --function-name arn:aws:lambda:us-east-1:361500002652:function:tcx_cli:PRD --cli-binary-format raw-in-base64-out --payload '[["<SAM_ACCESS_KEY>","<SAM_SECRET_ACCESS_KEY>","us-east-1.sws.siemens.com"],["samauth","CreateClient","<SAM_APP_ID>","<SAM_APP_NAME>","web"]]' secrets_output.txt
   ```

   **Windows:**
   ```cmd
   aws lambda invoke --region us-east-1 --function-name arn:aws:lambda:us-east-1:361500002652:function:tcx_cli:PRD --cli-binary-format raw-in-base64-out --payload "[[\"<SAM_ACCESS_KEY>\",\"<SAM_SECRET_ACCESS_KEY>\",\"us-east-1.sws.siemens.com\"],[\"samauth\",\"CreateClient\",\"<SAM_APP_ID>\",\"<SAM_APP_NAME>\",\"web\"]]" secrets_output.txt
   ```

### Result

If the process succeeds, open the 'secrets_output.txt' file, you will receive output similar to:

```json
{
  "clientId": "l7y3O03Y13PcI_hcAwr5M",
  "clientSecret": "3Y5MPNNcmaXeJMZubOxQZKy4WGRZpTJyl-ZQqauy_BprwrTRCMRBTMQhDj0cW1MU_PgZwOw3KlskcDouKYI4Yg",
  "expiry": 1789716486630
}
```

## Step 2: Update Secrets on HashiCorp Vault

1. **Retrieve Client ID and Client Secret**

   - Open the downloaded `.txt` file to find the `clientId` and `clientSecret`.

   ![alt text](image-1.png)

2. **Form a Credential String**

   - Create a string with the format:  
     `<clientId>:<clientSecret>`

3. **Encode the String in Base64**

   - Use PowerShell to encode the string:

     ```powershell
     [Convert]::ToBase64String([System.Text.Encoding]::UTF8.GetBytes("<clientId>:<clientSecret>"))
     ```

   ![alt text](image-6.png)

4. **Update the Vault with the New Credentials**

   - Take the base64-encoded string and clientId to update Vault.

5. **Navigate to the Credential Location in Vault**

    - Go to:  
      ```
      tcx/teamcenter/administration/client_credentials/common
      ```
    - Click on "Create new version" and update the necessary fields.

    ![alt text](image-7.png)

    ![alt text](image-8.png)

6. **Save the Changes**

    - After entering the new values, click "Save".

7. **Run the Password Rotation Workflow**

    - Execute the [Day N Password Rotation](../../020_Operations/050_Password%20Maintenance/020_On_Demand_Update/040_Day%20N%20Password%20Rotation/000_Intro.md) to complete the process.


> **Note: Always ensure the new `client_id` and `client_secret` are securely stored and that the base64 encoding step is completed before updating HC Vault. Only authorized personnel should perform these operations.**
