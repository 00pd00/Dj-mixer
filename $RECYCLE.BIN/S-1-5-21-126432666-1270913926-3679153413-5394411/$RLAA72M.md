# Ingress: Updating xAppIssuers and xAppUsers in an Existing Deployment

When rerunning, updating, or upgrading Teamcenter X deployments using the pipeline with updated values for `xAppIssuers` and `xAppUsers`, the new values will not be applied. This is because the pipeline does not support vault secret updates at this time.

This issue can occur during version upgrades, such as moving from tc14.3.1.3 to tc2506.0001 or from tc2412 to tc2506.0001.

In order to make the updates, follow these steps:

1. **Add `XAppIssuers` and `XAppUsers` to Vault**

   - For your existing Teamcenter X deployment, these key-value pairs must be added to Vault before running the update or upgrade process.
   - Store the values at the following Vault path:
     ```
     <environment-namespace>/tcx/automation/tcss/xapps
     ```

2. **Create a New Version and Update the JSON**

   - In Vault, create a new version of the secret.
   - Switch the view to JSON.
   - Add or update your keys for xAppIssuers and xAppUsers according to your SAM configuration (SAM 1.0/2.0 Client Credentials Grant or Token Exchange Grant).
   - Example entry:

     ```yaml
     {
       "client_whitelist": [
         "g6SxBOYPVeMOkuyyJ4_a_",
         "1GijGzVX_wTbqCIzY3Ju7"
       ],
       "service_users": [
         "g6SxBOYPVeMOkuyyJ4_a_:syntestdaemonuser",
         "1GijGzVX_wTbqCIzY3Ju7:adminconsoledaemonuser"
       ]
     }
      ```
     ![alt text](image-3.png)

> **Note:**
> 
> If the `cn` key (the `client_id`) already exists in your current deployment and you use the same value, Vault update or LDAP entry will be skipped for that mapping (e.g., `RSJhxFMbEmcwSojNGjl2Z:testuser1`).
>
> If a different `cn` key is provided, a new entry will be created in LDAP (e.g., `123456789123456789123:testuser`).
>
> The provided input for `XAppIssuers` and `XAppUsers` will override existing values in TcSS Component.

3. **Save Changes**
   - Save the updated JSON, including the newly added key-value pairs.

4. **Proceed with Update or Upgrade**
   - After successfully adding these values, you can continue with your update or upgrade process as planned. If you only need to update these secrets, you can simply run `modify_xapp_users` operation to complete the process.
      
## Troubleshooting: xApp OAuth Authentication Failure

The most common issue after performing the rotation steps is that the xApp cannot authenticate using OAuth token-based authentication. In this case, ensure the following:

- The `client_id` is whitelisted in TCSS
- The `client_id` is successfully mapped to a TC user

### Steps to Debug xApp Login Failure

#### Step 1: Check the QD File in the Tenant Repo

- Navigate to the tenant repository and verify that the client_id for the Admin Console or your xApp is present in the [QD file](https://gitlab.industrysoftware.automation.siemens.com/tcx-containers-deploy-automation/tcx-tenant-repos-dev/stdsso03-prd/-/blob/main/deploy_script/qd_stdsso03-prd.xml?ref_type=heads)

```yaml
<property id="fnd0_identity_oauth_clientWhitelist" value="1GijGzVX_wTbqCIzY3Ju7" />
<property id="fnd0_identity_oauth_clientWhitelist_2" value="1GijGzVX_wTbqCIzY3Ju7" />
```

- The QD file should contain a `client_id` entry — assert its presence and print the result to the console for confirmation
- If the `client_id` is missing, it needs to be added to the QD file before proceeding

#### Step 2: Check the identityservice.xml in the TCSS Pod

- Take the Cell ID from your inputs or config file
- Navigate to Rancher and locate the TCSS pod
- Check the following file inside the pod: /apps/tc/security_services/config/identity/identityservice.xml
- Search for the Admin Console or your xApp `client_id` entry within this file
- The entry may appear in a slightly different format — verify it matches the expected `client_id`
- If the `client_id` is absent or incorrect, this is likely the root cause of the authentication failure

```
<context-param>
	 <param-name>tcsso.oauth.client_whitelist</param-name>
	 <param-value>1GijGzVX_wTbqCIzY3Ju7</param-value>
	 <description/>
</context-param>
```

#### Step 3: Consistent Pre-prod vs. Prod Environments

- Make sure the environment type of the Admin Console or your xApp (i.e. Pre-prod vs. Prod) are consistent with your Teamcenter X deployment. A token generated by a pre-prod token endpoint cannot be used against a Teamcenter X instance using a prod endpoint.

In case the `client_id` is not properly registered (whitelisted) in TCSS, redo the steps again.
