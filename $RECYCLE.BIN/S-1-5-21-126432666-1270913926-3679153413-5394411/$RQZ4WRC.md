
## Prerequisites

We need a unique string that identifies a backup created at a given point in time. We refer to this as a **Backup Set Identifier.**
This backup set id will be used to tag and identify the various components of the containerized TcX environment backup.  
The backup set id follows the format below and will be auto-generated by the backup process. The identifier is quite readable and will allow the operator to understand the time at which the backup was taken.  

`<SOLDTO_ID>_<ENV_TYPE>_<TIMESTAMP_DDMMYYYY_HHmmss>`  

This identifier will be used during the next steps.

### Trigger automated backup using ansible job template

1. **Login to Ansible Tower**  
    Open a web browser and navigate to the Ansible Tower URL.  
    Log in with your Ansible Tower credentials.

2. **Access the Job Template**  
    Use TcX Backup Template link, please refer to [Ansible Templates Table](../../010_Tenant%20Onboarding/020_Basic%20Flow/020_Ansible%20Templates%20Table.md).

3. **Launch the Job Template**  
    Click the **Launch** button.

4. **Setting Up Credentials**  
    - If your AWS credentials are already configured on Ansible Tower, select them from the list.  
    - If not, you will be prompted to enter them in the survey. Click **Next** to proceed.
    - For **Azure**: Keep all selections as it is and Click **Next** to proceed.  

#### 5.1 Fill in the Survey for AWS

Fill in the fields from other prompts with the appropriate values:  
- **customer_id**: Enter the customer ID.  
- **description**: Enter the description.  
- **environment_type**: Enter the environment type as `prd`, `uat`, etc.  
  *(Note: If the environment_type includes a postfix, such as `prd012`, treat '012' as the environment_id and provide it in the environment_id field below.)*  
- **environment_id**: Enter the environment id (keep it empty if environment_id is not present).  
- **stream_id**: Enter the stream ID as `dev/customer/dryrun/internal`.  
- **mode**: Enter the mode as `Backup`.  
- **region**: Enter the environment's AWS region, e.g., `us-east-1`, `eu-central-1`, etc.  
- **tier**: Enter the tier based on the tenant, e.g., `std`, `silver`, or `gold`.  
  *(Note: For `std` - backup will be taken after every 24 hrs., `silver` - after 12 hrs., and `gold` - after 2 hrs.)*  
- **pipeline_variable_version**: Enter the pipeline variable version. If this field is not present, then add it manually.  
  Example: `"pipeline_variable_version: 3.0.4"` without quotes. 
- (optional) **PipelineCliVersion**: TcxCliRequirement which can be provided.

Click **Next** to proceed.  

A survey will appear. Fill in the survey with appropriate values:  
- **AWS_ACCESS_KEY_ID**: AWS access key of the account where ENV is present, with a duration exceeding 2 hours.  
- **AWS_SECRET_ACCESS_KEY**: AWS secret access key of the account where ENV is present, with a duration exceeding 2 hours.  
- **AWS_SESSION_TOKEN**: *(Optional)* Session Token of AWS - Provide only when using temporary credentials, with a duration exceeding 2 hours.  
- **GITLAB PAT**: Personal Access Token of GitLab.  
- **VAULT TOKEN**: Token of Hashicorp Vault.  For backup, the ROOT TOKEN is required. The pipeline token (customer_inputs) will not work for this case. See Root Token in [Tools Setup](../../000_Cell-Setup/000_Automation%20Prerequisites/070_Tools%20Setup/000_Vault%20Setup.md)

*Note: These AWS credentials should be tenant account specific, where the customer resides. These credentials should have at least read-level access to all the AWS services we deploy. Otherwise, copy the permissions of `<env_type>-<CustomerID>-Role` and attach these permissions to the user that you wish to generate credentials for. Use these credentials to pass them from Ansible Tower.*  

*Note: You can either provide AWS credentials as input or select them as a Tower credential while running the template.*

#### 5.2 Fill in the Survey for Azure

Fill in the fields from other prompts with the appropriate values:  
- **customer_id**: Enter the customer ID.  
- **description**: Enter the description.  
- **environment_type**: Enter the environment type as `prd`, `uat`, etc.  
  *(Note: If the environment_type includes a postfix, such as `prd012`, treat '012' as the environment_id and provide it in the environment_id field below.)*  
- **environment_id**: Enter the environment id (keep it empty if environment_id is not present).  
- **stream_id**: Enter the stream ID as `dev/customer/dryrun/internal`.  
- **mode**: Enter the mode as `Azure Backup`.  
- **region**: Enter the environment's Azure region, e.g., `eastus`.  
- **tier**: Enter the tier based on the tenant, e.g., `std`, `silver`, or `gold`.  
  *(Note: For `std` - backup will be taken after every 24 hrs., `silver` - after 12 hrs., and `gold` - after 2 hrs.)*  
- **pipeline_variable_version**: Enter the pipeline variable version. If this field is not present, then add it manually.  
  Example: `"pipeline_variable_version: 3.0.4"` without quotes.  
- **CellId**: Enter the CellId.  
  Example: `"CellId: azm-eaus-tcx-preprod47-dev-005"` without quotes.  
- **PipelineCloud**: Enter the PipelineCloud.  
  Example: `"PipelineCloud: '109407702'"` without quotes.  
- **orchestrator_version**: [Version of the tcx-backup-core](https://gitlab.industrysoftware.automation.siemens.com/tcx-deploy/tcx-backup-core/-/blob/main/pyproject.toml?ref_type=heads#L3). This is an optional parameter.
  Example: `"orchestrator_version: 1.6.115.2"` without quotes.
Click **Next** to proceed.  

A survey will appear. Fill in the survey with appropriate values:  
- Leave **AWS_ACCESS_KEY_ID**, **AWS_SECRET_ACCESS_KEY**, and **AWS_SESSION_TOKEN** fields blank in the survey. 
- **GITLAB PAT**: Personal Access Token of GitLab.  
- **VAULT TOKEN**: Token of Hashicorp Vault.  For backup, the ROOT TOKEN is required. The pipeline token (customer_inputs) will not work for this case. See Root Token in [Tools Setup](../../000_Cell-Setup/000_Automation%20Prerequisites/070_Tools%20Setup/000_Vault%20Setup.md) 

6. **Confirm and Launch**  
    Review the summary page to ensure all settings and survey responses are correct.  
    Click **Launch** to start the job template.
