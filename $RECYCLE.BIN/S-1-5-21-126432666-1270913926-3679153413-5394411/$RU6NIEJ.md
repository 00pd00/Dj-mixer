## Vault contains empty client_id and client_secret for the Samauth configuration

Occasionally, the pipeline may fail to create new SAM client, or client_id or client_secret,  due to insufficient permissions in the Samauth user policy, resulting in empty values being written to the vault. If the necessary policies are added to the Samauth user and the pipeline is rerun, a new SAM client will be created, generating a new client id and client_secret . However, the pipeline does not support overriding secrets in the vault (by design). In such cases, it is necessary to manually delete the existing secret from the vault before rerunning the pipeline. Upon rerun, the pipeline will create a new SAM client, generate the new client_id andclient_secret and, and push them to the vault.
